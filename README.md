# pocketport-anything
AI-powered game porting for Nintendo 3DS. Reverse engineer, adapt, optimize, build, and test playable ports.

> **PocketPort Anything** is a research-led, open-source *porting toolchain*, not an emulator, universal binary converter, or a way to run Switch executables on a 3DS. Its working capabilities are explicitly documented and tested.

## What already works

- Python CLI for inventory (including SHA-256 and file signatures), game-workspace initialization, evidence-based route selection, toolchain diagnosis, manifest reporting and reproducible command logs.
- A **defined PocketPort IR** subset with a real parser, interpreter, C translator, C compiler integration and behavioral equivalence tests. This translates PocketPort IR—not arbitrary ARM64, MIPS or x86 binaries.
- An original, playable **Star Catcher** C game core with reproducible native/3DS frontends. The game's scoring function is generated by the IR translator and linked into the shared game core.
- An original native 3DS graphics/input/RomFS example using libctru and citro2d. 3DS compilation requires the devkitPro toolchain; host tests do not demonstrate console launch.
- Batch image preparation using Pillow, power-of-two texture padding, budgets/profiles, and optional real `tex3ds` conversion if installed. Unsupported inputs cause explicit diagnostics; the Pillow stage is not a PICA200 encoder.
- Evidence levels, command provenance, an isolated public/private asset boundary, documented integration with REA, and Python/C host-side regression tests.

## Quick start

Requires Python >= 3.10; the CLI's inventory, planning and translation features use only the standard library.

```bash
python -m pocketport doctor
python -m pocketport inspect examples/asset-pipeline/assets
python -m pocketport plan examples/asset-pipeline/assets --target new3ds
python -m pocketport translate examples/translation-demo/score.ppir --out /tmp/pocketport-ir
python -m pocketport verify-ir examples/translation-demo/score.ppir
python -m unittest discover -s tests -v
```

For image processing: `python -m pip install -r requirements-optional.txt`.

```bash
python -m pocketport init /tmp/my-port --game "Example Game" --target new3ds
python -m pocketport optimize examples/asset-pipeline/manifest.json --out /tmp/pocketport-assets --profile balanced
python -m pocketport build examples/source-port/project.json --host
python -m pocketport test examples/source-port/project.json --host
python -m pocketport report examples/source-port/project.json --out /tmp/pocketport-report.json
python -m pocketport demo --out /tmp/pocketport-unified-demo
```

Run the host Star Catcher binary after the build with `./examples/source-port/build-host/star-catcher-host --script RRRLLLNNNN` (on Windows use `.exe`). Host simulation is not 3DS validation.

## Nintendo 3DS builds

Install the **devkitPro 3DS toolchain**, including devkitARM, libctru, citro3d/citro2d, and required 3DS packages. The host-side `doctor` command detects known tools. From the repository root:

```bash
python -m pocketport build examples/source-port/project.json --console
# or
make -C templates/3ds-homebrew
```

These commands deliberately fail if the necessary toolchain is missing. The output of a successful devkitARM build is only *buildable* evidence (Level 2), not proof of emulator, hardware, or full-game compatibility.

## Project layout

`pocketport/` is the host-side orchestrator; `runtime/core/` is the portable C game core and native runtime boundaries; `templates/3ds-homebrew/` is a standalone original console program; `examples/source-port/` is an original C interactive game; `examples/translation-demo/` holds a precisely scoped, executable IR demonstration; `docs/` contains verified sources, limitations and porting playbooks.

## NUP v1 metadata (read-only)

`python -m pocketport inspect-nup /path/to/authorized.nup` authenticates an NUP v1 table of contents and prints package-level identifiers without extracting or executing any file. This is a host-side diagnostic informed by the publicly documented Lichii archive structure; it is **not** a Switch 2 to 3DS port or a proof of game identity. See `docs/ZELDA_CASE_STUDY.md` and `docs/PORT_REFERENCE_IMPLEMENTATIONS.md`.

The PPIR translator also supports `and`, `or`, `xor`, and masked `shl`/`shr` (uint32) with compiled reference-equivalence tests; it still does not accept machine-code binaries.
